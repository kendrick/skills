## The taste calls

**The third record, which was the task.** I made it a sibling of the record that *does* get stamped rather than a stranger to it. Both are `accepted` v2 Context records about the same overnight job in Harrow. The transcript spends a long passage on that job (Deshawn explaining the 01:00-04:00 write window, which is the confirmation) and then spends another passage on who builds the day's run after the pilot, which is the route record's exact territory. Fiona pitches Quillon's routing module and says it "sequences on drive time" — the record's own discriminator, in the room, attached to a different system as a sales pitch. So a model that stamps on topical adjacency has every reason to stamp it: right system, right subsystem, right vocabulary, adjacent passage.

What nobody does is restate the claim. The record says Harrow orders stops by meter route code and not by drive time; the meeting asks where runs will be built in future and never touches how they are ordered today. I deliberately kept anyone from saying "the run comes out of Harrow" or "Tanager just renders it," both of which would have restated a piece of the record and made the row arguable instead of binary.

**Grading off file state, not off judgment.** Every negative row is "byte-identical, still no `last_confirmed:` line." The grader never has to decide whether something was confirmed; they compare files. That also let me build the fixture so exactly one file in the scope carries a `last_confirmed:` line going in and exactly one carries it coming out, which makes the whole scenario checkable with a single recursive grep.

**One row is not off the staged copy, on purpose.** The phase 6 row is graded against the run's report. I kept it because byte-identity alone is a weak assertion for the v1 record: a run that never looked at v1 records at all passes that row by doing nothing. The `skipped:` line naming the generation is the only evidence the run actually judged the v1 record confirmed and the stamper declined it. I called that exception out in the scenario preamble rather than hiding it, since C-14 asks for rows settleable off the copy and this one is the exception.

**I also moved a fifth enumeration the task did not name.** Line 3's "contradiction handling, chronic open questions, scope proposal, and what a Tier 2 summary is allowed to say" is a census of what the suite covers, and a fifth scenario makes it stale in exactly the way the constitution keeps flagging. I added "and telling a confirmation apart from a mention." This is the one place I read past the letter of the spec excerpt; it seemed like the faithful reading of "every enumeration moves together," and it breaks none of C-14's greps. Flagging it as a judgment call in case the checker disagrees.

**`:130` revised.** The new scenario does change what is true of the set. Four of its six rows pass for a run that never opens `_memory/`, so its raw row count reads better than it deserves. I appended two sentences saying so and kept the original sentence about 1 and 4 intact.

**Voice.** I matched the file rather than my own defaults: American spelling in the editorial prose ("behavior", "crystallizing", "cutover"), British in the in-world fixture ("mobilisation", "optimised", "licence"), which is what the Meridian fixture already does with "utilisation". Spaced em dashes in the scenario heading and the fixture bullet, because the four siblings use them and a fifth entry that punctuated differently would look broken.

## Ambiguity worth naming

The spec's fixture table says the `proposed` record is "not stamped — nothing has agreed to it yet," but SKILL.md's phase 2.5 says only `accepted` records can be confirmed at all. So a careful run may never hand the proposed record to the stamper, and a less careful one will hand it over and get a `skipped:` line. Both are correct behavior and the record is unchanged either way, so I graded the record's file state and left the proposed record out of the phase 6 row. Requiring it to appear in the skipped list would have failed a run that did the more precise thing.

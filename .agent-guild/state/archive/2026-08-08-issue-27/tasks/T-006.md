## Spec excerpt

One file, one comment: `_maintenance/inbox-to-memory/eval-scope.sh`, line 6.

It reads, inside the header comment block:

> the migration tests hold themselves to the same rule and say why at tests/inbox-to-memory-smoke.sh:1226.

The rule it means — that checked-in fixtures are never written in place — is the commented guard that begins "The checked-in fixtures are never migrated in place." Two things are wrong with the citation:

- **It was already wrong before this job.** Line 1226 is a `# ---` divider opening the "v1 link checking (#32)" section. The rule it points at lives around line 1296.
- **It has since moved again.** T-004 inserted a new section into the smoke suite above that guard, so whatever line number you compute today is a number that will rot the next time anyone touches the file.

So do not simply correct the number. **Rewrite the citation to a form that does not depend on one.** The guard's comment text is greppable and its line number is not — point at the rule by what it says, or by the guard's variable, or by naming the section. Any form that survives an insertion above it is fine; a corrected line number is not, because it re-creates the same defect one edit later.

Keep the sentence reading as the same helpful aside it is now. The comment explains why `eval-scope.sh` stages a private copy instead of running against the committed fixture, and the citation is there so a reader can go see the same rule enforced next door. That purpose survives the rewrite.

### Verify it yourself before you finish

```bash
/usr/bin/grep -rnoE 'inbox-to-memory-smoke\.sh:[0-9]+' _maintenance/ inbox-to-memory/ tests/
```

If that returns nothing, the citation is stable. If it returns a hit, open the cited line and confirm it genuinely says what your comment claims — a pointer that resolves to a real line saying something else is worse than one that resolves to nothing.

This is a prose edit, not a substitution. The sentence has to still read as the aside it is, so do not mechanically swap the number for a quoted string and leave the grammar behind it broken.

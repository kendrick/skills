## Taste calls

**The instruction's wording: "Paste the paragraph below into the scope's
patterns journal."** Printed above the record, "this paragraph" points at
nothing, so the reference had to turn around. "the paragraph below" is the
plainest forward pointer available and it survives the reader glancing away
mid-scroll; "the following paragraph" reads stiffer for no gain. Keeping the
verb, the object, and the destination in the same order as the old sentence
also means anyone who has run this script before does not have to reread it.

**The leading blank line stayed on the instruction, not the record.** The old
`printf` opened with `\n` to hold the record off the summary block. I moved
that blank to the new first line rather than dropping it, so the two-line
offer still reads as one unit set apart from the machine output above it.
The blank between instruction and record is the one C-3 asks for.

**`links_noun`, computed inside the block.** The spec warned that hoisting a
plural variable up next to the counters fails C-7, and it is right that the
hoist is the tempting shape. It sits inside `failures -eq 0`, three lines
above its only use. Written as a full `if` rather than `[[ ... ]] && x=y`,
which under this script's `set -e` would abort the run on the false branch.

**Only the link counter changed.** `lint failures`, `renames`, and
`deletions` reach the record at zero or never, so their plurals are already
correct. Touching them would have been churn against three assertions for no
reader-visible gain. The comment inside the block now says why, since the
asymmetry looks like an oversight otherwise.

**The negative needle is "patterns journal", deliberately wide.** Both the
record-isolation check and the combo check grep for that fragment rather than
a full sentence. Any paste directive has to name the destination, so a
reworded instruction welded onto the record still trips it, where a check
pinned to today's exact sentence would go quiet the next time someone edits
the prose. The record never legitimately mentions the journal, so it cannot
false-positive.

**Comment prose.** Ran through the humanizer. It caught diff-anchored
phrasing in three of the four new comments ("the needle moved with the
prose", "the old one", "now") and I rewrote them to describe the shape as it
stands rather than narrate the edit. Kept the file's ` -- ` aside idiom.

## C-10, and why no doc changed

Read both sentences against the run above before settling the wording.
`migration.md:148` and `SKILL.md:406` each say a passing run *ends* by
printing the paragraph, ready to paste, that it goes to stdout and nowhere
else, and that a failing run prints none. All four claims still hold: the
record is line 11 of 11, stderr is empty, and the combo case prints neither
line. Printing the instruction first is what preserves this. Had I put the
instruction last, both sentences would have needed surgery.

## Ambiguity I resolved rather than invented around

C-3 asks for "instruction, blank line, record, end of output" and does not
say whether a blank line may precede the instruction. I kept the one that was
already there, reading the clause as governing the relationship between the
two new lines rather than forbidding the separator the old output had. If a
checker reads it the other way, the fix is deleting one `\n` from the first
`printf`.

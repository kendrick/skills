## Spec excerpt

Build one fixture under `tests/fixtures/inbox-to-memory/evals/` for evaluating migrate mode's Tier 2 behavior: the `summary` and `entities` a model proposes for a note. You are building the fixture only. The scenario that grades against it is a separate task.

Read `inbox-to-memory/SKILL.md`'s "Tier 2: Summary and Entities" section before starting. The mechanism, in short: `migrate-scope.sh --tier2-extract <dir>` writes one `<note-id>.extract.md` per note, holding that note's sections down to `## Raw Content` and no further, plus a `proposals.yaml` skeleton with `summary: ''` and `entities: []` waiting to be filled. A proposal is then judged against the extract and against nothing else.

**The trap this fixture has to avoid.** `--tier2-extract` emits only for v1 notes. A note carrying `schema: 2` is skipped whole by the migrator and produces no extract at all. Build the gradable notes as v1 — no `schema` key — or the scenario grading them has no file to grade against and every one of its pass conditions becomes unfalsifiable. Verify by running the extract yourself and confirming a file appears for each note you intend to be graded.

**What to plant.** The scenario this feeds will grade two things, so the fixture needs to make both decidable by reading the extract:

- **Entities.** Names that appear verbatim in the extracted sections, so a correct proposal is checkable. Also plant at least one name that appears *only* below `## Raw Content` — an unreviewed transcript name, ideally a mishearing of someone real. A proposal listing it is wrong, and the migrator rejects it with `tier2-entity-unsourced`. That contrast is the point of the fixture.
- **Summary.** Sections carrying enough substance that a one-line summary is possible, and at least one fact that lives only in raw content — a date, a decision, an outcome — so a plausible-sounding summary asserting it is demonstrably unsourced. The failure this scenario exists to catch is a summary that reads well and reports something the reviewed layer never said.

**Constraints.**

- Follow the file shapes of the existing `old-only` fixture, which is a v1 scope. Match its conventions, including nanoid-suffixed filenames and the section order in `assets/note.template.md`.
- The scope must be opted in: `_inbox/` plus `_memory/`. `_inbox/` may be empty with a `.gitkeep`; this fixture is for migrate mode, not process mode.
- No `MEMORY.md`, `INDEX.md`, or `index.md` under any `_memory/` path. The smoke suite walks the whole fixtures tree for those.
- `inbox-to-memory/scripts/lint-scope.sh` must pass over the fixture. Run it — but do not read its exit 0 as saying your tokens are well formed. Its token-grammar pass runs only over files carrying `schema: 2`, and this fixture is v1 throughout, so it reads none of your tokens at all. Match every inline token you write against the ten-row grammar table at `references/machine-contracts.md` yourself. The rule is scoped to note bodies above `## Raw Content` — brackets in frontmatter and brackets inside raw content are legal and are not tokens, which matters here because this fixture deliberately plants content below that fence.
- The migrator refuses to run `--apply` on a dirty tree, but `--tier2-extract` writes nothing to the scope and is safe to run mid-task. Stage its output in a temp directory, never in the repo.

Content should read like a real working session. A fixture of filler gives the extract nothing to summarize, and then the scenario grades nothing.

Touch nothing outside your one new directory under `tests/fixtures/inbox-to-memory/evals/`. Do not update `tests/fixtures/inbox-to-memory/README.md` — its staleness is a declared non-goal and editing it fails C-1. Do not commit.

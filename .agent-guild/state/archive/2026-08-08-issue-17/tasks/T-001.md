## Spec excerpt

Build `_maintenance/inbox-to-memory/eval-scope.sh`, the staging script for the inbox-to-memory eval suite. It is one of three deliverables for that suite; you are building only this one. The doc that will call it and the fixtures it will copy are separate tasks, and neither exists yet.

**What it does.** Given the name of an eval fixture, copy that fixture into a fresh scratch directory outside the repo and print the staged path on stdout. Nothing else goes to stdout, because the caller will capture that path.

**Why it exists.** The eval scenarios run the `inbox-to-memory` skill in process mode against a fixture. Process mode deletes every file from the scope's `_inbox/` once it has groomed it, and writes new notes into the scope. Run against a committed fixture in place, the first scenario destroys the fixture for every scenario after it. This repo already holds that rule for its migration tests and says why at `tests/inbox-to-memory-smoke.sh:1226`; read that comment before you start.

Staging is per run, not per fixture. Each scenario runs twice, once with the skill loaded and once without, and the two runs each need their own copy — the first empties `_inbox/`, so a baseline sharing the directory would grade against nothing. The script gets called once per run, and every call mints a new scratch directory.

**Interface.** Fixtures live under `tests/fixtures/inbox-to-memory/evals/<name>/`. Take the fixture name as the argument. That directory will not exist yet when you build this — the fixtures are T-002 and T-003 — so test against one of the existing scopes under `tests/fixtures/inbox-to-memory/` (`old-only`, `mixed`, `journal-v1`) and make the script work for any directory name under the evals path.

**Requirements.**

- Exit nonzero with a message on stderr when the named fixture does not exist. A scenario staged from a typo should stop, not run against an empty directory.
- The staged copy is faithful: `diff -r` between source and staged tree comes back clean.
- Write nothing anywhere but the scratch directory. `git status --porcelain` must be identical before and after a run.
- Scratch lives in the OS temp directory, via `mktemp -d`. Never inside the repo.
- Do not delete the scratch directory on exit. The caller runs the skill against it after the script returns, and a trap that cleans up would pull the ground out from under them.

**House constraints.** `grep -q` is unreliable here — a hook rewrites commands, and the same hook shadows `cat` and `stat`. Prefer capturing output and testing with `test -n` / `test -z`, and use `wc -c` for sizes. Match the shell idiom of the existing scripts in `inbox-to-memory/scripts/`; read `verify-migration.sh` for the house style.

Comment the why, not the what. The one comment this script genuinely needs is the reason it exists at all, and `tests/inbox-to-memory-smoke.sh:1226` is the precedent to point at.

Touch no file but `_maintenance/inbox-to-memory/eval-scope.sh`. Do not commit.

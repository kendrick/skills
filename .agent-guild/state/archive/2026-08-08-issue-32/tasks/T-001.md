## Spec excerpt

`inbox-to-memory/scripts/lint-scope.sh` reports a broken wiki link in a v2 note and stays silent on the identical link in a v1 note. A v1 file is one carrying no `schema:` key in its frontmatter; that is the only version discriminant, decided by `has_schema_key` at `:82-89`.

**Where it happens.** Pass one spans `:414-432` and classifies each file, collecting only the v2 ones. The block below is `:421-426`:

```bash
if ! has_schema_key "$file"; then
  v1=$((v1 + 1))
  continue
fi
v2=$((v2 + 1))
v2_files+=("$file")
```

Pass two at `:435-462` then iterates `v2_files` alone, so a v1 file never reaches `check_links` at `:366-380` at all. That `continue` predates the body-grammar gate at `:444-451` and is doing more work than the gate intends.

**What to change.** A v1 file must reach `check_links`, and must reach nothing else. Everything below is a hard boundary, not a preference:

- `check_frontmatter`, `check_counts`, and all six body-grammar checks behind `has_v1_body` (`check_tokens`, `check_open_questions`, `check_tensions`, `check_contradictions`, `check_decisions`, `check_anchors`) must continue to skip v1 files entirely. A v1 note predates the token grammar, the anchor rule, and the four derived count keys.
- The open-question-resolution loop at `:458-461` must continue to skip v1 files, **and** a v1 body must contribute nothing to the scope-wide `$work/open-slugs` set built in pass one. That set feeds both that loop and the `RECURRING` report at `:471-475`. Harvesting v1 slugs into it is the quietest way to get this wrong: every check command in the constitution passes except C-3's second block, and a question resolved in a v2 note that no v2 note ever opened silently stops being reported.
- The `v1 files:` and `v2 files:` counts must not move for any scope. Do not reclassify v1 files as v2 to get them into pass two — C-4 catches it immediately, and it would fail 14 previously-legal assertions on `old-only`.
- `check_links` reads an extracted body, not the raw file. `extract_body` at `:208-216` stops at `## Raw Content` and strips HTML comments; a link below that fence is out of scope by design. Pass one currently caches a body per v2 file into `$work/body.$index`. A v1 file needs the same treatment for its links to be checkable, and `fail` reports `$current_file`, so that variable must name the v1 file when its links are checked.

**You own `inbox-to-memory/scripts/lint-scope.sh`'s code, and nothing else in the repository.** Two sibling tasks are running against this same tree and each owns files you must leave alone. Do not add or modify anything in `tests/inbox-to-memory-smoke.sh` — that suite is T-002's, and your job is only that it stays green, not that it grows. Do not correct `inbox-to-memory/references/machine-contracts.md`, `inbox-to-memory/references/migration.md`, or `inbox-to-memory/SKILL.md` even though your change makes sentences in all three false; repairing them is T-003's entire task. When you are done, `git status --porcelain` should list `inbox-to-memory/scripts/lint-scope.sh` and nothing else. Note that C-6's allowlist deliberately permits all five paths, so it will not stop you from straying — this boundary is enforced by reading, not by a script.

**Out of scope, and enforced by C-9.** Do not add any check. Do not widen any existing check. Do not touch the comments at `:10-12` or `:441-443` — those are T-003's, and rewriting them here will collide with that task. Do not fix the `EXIT` trap chain in `tests/inbox-to-memory-smoke.sh` (that is issue #30, deliberately left alone). Do not add a counts check for v1 files; a v1 note carries none of the four keys, so there is nothing to compare.

**A risk worth knowing.** No v1 note in any scope has ever been link-checked. Against a real vault the first run may surface a backlog of genuine breakage, and that output will look like this change caused it. It did not. Inside this repo's fixtures the change is silent: exactly three wiki links exist in v1 files, all in `evals/contradiction-amend`, and all three resolve by filename.

**Verify with** the commands in your task's `check_method`, all of which are stated in full in `.agent-guild/state/constitution.md`. Every one of them was run against the unfixed tree before this task was written, so they work as written.

## Spec excerpt

T-001 makes `inbox-to-memory/scripts/lint-scope.sh` run `check_links` on v1 notes (files with no `schema:` key), where it previously skipped them entirely. Nothing in the test suite pins that behavior, so a later refactor would silently revert it. Add durable coverage to `tests/inbox-to-memory-smoke.sh`.

**Four cases are required.** Each must assert something specific, not merely that the suite still exits 0:

1. A wiki link in a v1 note resolving to no file in scope is reported as `link-broken`.
2. A v1 link whose target matches a filename in scope is **not** reported.
3. A v1 link whose target matches no filename but whose trailing ten characters match the id embedded in a filename is **not** reported. `check_links` at `:376-377` is the fallback that resolves it. No existing fixture exercises this path on a v1 file, which is why it needs its own case.
4. A v1 note carrying an unregistered token, an open-question slug nothing else opens, a malformed tension, a malformed contradiction, a malformed decision, and a bare `(raw: line 12)` anchor still passes. This is the guard against over-correction: those six would all fail if the body-grammar checks began running on v1 bodies.

**How to build them.** Follow the file's existing idiom rather than inventing one:

- Build each scope with `mktemp -d "${TMPDIR:-/tmp}/i2m-<name>.XXXXXX"` and populate it by copying a fixture (`cp -R "$fixtures/old-only/." "$scope/"`). Never write into `tests/fixtures/` — the suite's closing guard at `:1229` hashes the whole fixture tree and aborts if anything moved.
- Use the helpers already defined at the top of the file: `run_lint` (`:98`), `require_line` (`:49`), `require_output` (`:75`), `require_failure` (`:63`), `refute_failure` (`:85`), `require_dir` (`:21`), `require_text` (`:28`), `refute_text` (`:39`). For "this scope passes," the file's own idiom is `require_line "$out" "failures: 0" <label>`, used at `:125` and `:132` — reach for that rather than inventing an assertion.
- Inject body content **above** the `## Raw Content` fence. `extract_body` stops there, so a link below it is out of scope by design and would make case 1 assert nothing.
- **The trap convention is load-bearing.** Every scratch path in this file is cleaned by an `EXIT` trap that re-lists every path from the trap before it, accumulating down the file. Your first added trap must carry every path listed in the existing trap at `:1203`, plus your own. If you add a second scope, its trap must carry everything the first one did, plus the new path. Do not start a fresh trap listing only your own paths — that silently orphans every earlier scope on an early exit.

Two scopes are enough for all four cases: one that must fail (case 1) and one that must pass (cases 2 through 4 can share a scope, since none of them may produce a failure).

**Out of scope.** Do not repair the file's two pre-existing trap gaps — `$overrun_scope` created at `:195` and dropped by the trap at `:239`, and `$tpl_scope` created at `:345` and dropped at `:625`. That is issue #30 and it is deliberately not this job's business. Do not add a checked-in fixture directory; build everything at runtime in scratch. Do not modify `inbox-to-memory/scripts/lint-scope.sh` — T-001 owns it.

**Sanity check your own work.** Each of the four cases should fail if run against the lint as it was before T-001. If a case passes either way, it pins nothing and needs rewriting.

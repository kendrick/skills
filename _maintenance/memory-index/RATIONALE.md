# memory-index—rationale

Evidence tiers: **[E]** measured or observed in a real run, **[P]** practitioner reasoning from prior art, **[C]** convention inherited from this repo or its neighbors.

## Where This Came From

Five sources:

- **Issue #192**, which set the two modes, the `<scope>-<type>` naming, the rule that folders and not frontmatter decide collections, and both falsifiers. Its follow-up comment, written after #193 landed, added the v1-body and journal-candidate limits below.
- qmd's README (https://github.com/tobi/qmd)—`qmd collection add <path> --name <n> [--mask "<glob>"]` with a default mask of `**/*.md`, `qmd context add qmd://<n> "<text>"`, `qmd update`, `qmd embed`, and the MCP server entry `{"command": "qmd", "args": ["mcp"]}`. It also says a collection's `ignore` list is YAML-only, and no CLI command sets it.
- **`inbox-to-memory`'s scaffold trees**—records at `<scope-root>/_memory/<type>/<slug>-<nanoid>.md` in `decisions`, `context`, and `rules` (lightweight) or `policy-rules` and `exceptions` (canonical), groomed notes directly in `notes/`, and the `## ... in One Paragraph` and `## Record Types` sections the context strings read.
- #193's sidecar (merged as #255)—raw text moved to `notes/raw/<id>.md`, so an index could exclude it.
- **Issue #374**, which asked for a refresh cheap enough to run from a per-turn hook, set the one-second bound and the run-once-under-two-calls rule, and named `notes/raw/` and `notes/_inbox/` as the falsifier for which files count as changed.

## Decision Ledger

| # | Decision | Why | Tier |
|---|---|---|---|
| 1 | Model-invocable (no `disable-model-invocation`) | A misfire is cheap: Step 1 runs `--dry-run` first and registers nothing without a yes, and `qmd collection remove` undoes a registration. Making it user-invoked would also mean adding it to `AGENTS.md`'s user-invoked list, which costs more than this description does. | [P] |
| 2 | One stdlib script, `scripts/memory-index.py`, with two subcommands, `register` and `refresh` | Registering is a fixed sequence of commands built from the directory tree, which is a job for a script rather than a fresh act of judgment every run, so every scope comes out registered the same way. Standard library only keeps the skill copy-in portable, per `AGENTS.md`. | [C] |
| 3 | Collections keyed on folders, and the script never opens a record | Issue #192's rule: a file belongs to `<scope>-<type>` exactly when it sits under `_memory/<type>/`. The folder is what the scope owner moves, and qmd's structured filter reads only a nested `qmd.metadata` block, which this repo's single-line frontmatter lint forbids. A frontmatter value that disagrees with its folder is the lint's to report. The smoke suite pins this with both falsifiers. | [P] |
| 4 | The notes collection excludes `notes/raw/` with `--mask "*.md"`, not with qmd's `ignore` list | qmd's README says `ignore` is YAML-only and no CLI command sets it, so using it would mean writing qmd's `index.yml`. Probed against qmd 2.8.3 (`facd35e`) on 2026-10-27 in an index isolated by `QMD_CONFIG_DIR`, `XDG_CONFIG_HOME`, and `XDG_CACHE_HOME`: `--mask "*.md"` on `notes/` indexed `notes/2026-10-27-a.md` and not `notes/raw/x.md`. The cost is that `notes/CLAUDE.md` and `notes/README.md` get indexed too. | [E] |
| 5 | Context strings come from the scope's `CLAUDE.md` "in One Paragraph" section and the type's bullet under the `_memory/CLAUDE.md` heading that starts `Record Types`, with `Memory scope <scope>.` as the fallback | Those files are where `inbox-to-memory`'s scaffold already writes what a scope is and what each record type holds, so the context restates the owner's own words and goes stale only when they do. A paragraph still holding its `<!-- Fill in -->` comment would put template text in every context, so comments are stripped and an empty result falls back. The script finds the type's bullet by its label (the first bold span, else the first backticked span, else the leading run of capitalized words), never by the whole line, because a description can name another type: "a choice made under standing rules" put the Decision line on the rules collection (PR #266 review). A bullet whose label is neither bold nor backticked and doesn't open with a capitalized word can still miss. | [P] |
| 6 | `register` runs `--dry-run` first and runs for real only on the user's yes | It writes into the user's qmd index, which other scopes share. Showing the exact commands first is what makes model-invocation (row 1) safe, and a dry run costs nothing. | [P] |
| 7 | Exit codes 0 pass, 1 a qmd command failed, 2 usage error, 3 not a memory scope or qmd not on PATH | Follows the validator convention `check-territories.py` set and `AGENTS.md` names for scripts that gate a run, except that a usage error exits 2, because argparse exits before the script's own code runs. A failed `collection add` stops the run at that command, with `FAILED: <command>` and qmd's first stderr line, so a half-registered scope is never reported as done. | [C] |
| 8 | `refresh --if-changed` reads collection paths and patterns from a cached stamp and never calls qmd | The issue said to read them from `qmd collection show`. Measured against qmd 2.8.3 (`facd35e`) on 2026-11-19 in an index isolated by `QMD_CONFIG_DIR`, `XDG_CONFIG_HOME`, and `XDG_CACHE_HOME`, every qmd call took 3–4.8 s of wall time, `qmd --version` included, so one `collection list` alone breaks the one-second bound. Plain `refresh` already pays for qmd, so it runs `collection list` and one `collection show` per name and caches the results. A shim that sleeps 3 s on every call pins the hot path (cases 11 and 12). | [E] |
| 9 | The stamp is `last-refresh.json` under `${XDG_STATE_HOME:-~/.local/state}/memory-index/`, and it records the time the refresh started | The state dir follows the XDG base-directory spec and sits outside every scope, so no scope's git tree picks up a file that changes every turn. `refresh` takes the start time just before `qmd update`. A file written while `update` or `embed` runs is then still newer than the stamp, and the next hook call refreshes again. An end-time stamp would mark that file as indexed when it wasn't (case 14). A failed run writes no stamp. | [P] |
| 10 | A hook refresh holds an `fcntl.flock` on `refresh.lock` for its whole life | Stop fires after every turn, so two hook calls can land inside one multi-second refresh. The parent takes the lock with `LOCK_EX \| LOCK_NB` before the spawn and passes its fd to the child, so a second call a millisecond later finds the lock held. The kernel drops the lock when the child exits, even on SIGKILL, so a killed refresh can't strand it and no caller has a stale lock to reclaim. The first design used an `O_EXCL` lock file that went stale after an hour. Two callers could both read an hour-old lock as stale, one unlinked the lock the other had just taken, and both spawned a refresh (PR #376 review). `refresh.lock` stays on disk between refreshes, and only its flock shows that a refresh is running. | [P] |
| 11 | `--if-changed` prints nothing on stdout and exits 0 on every branch, and the detached child writes to `refresh.log` | Claude Code adds a SessionStart hook's stdout to the agent's context, and a Stop hook that exits 2 blocks the stop. Any output or nonzero exit from this mode would leak into the session. Diagnostics go to stderr as one line. The child gets `stdin` from `/dev/null` and its stdout and stderr go to `refresh.log`, so the hook's pipes close when the parent exits and the harness never waits on the refresh. | [P] |
| 12 | A missing or unreadable stamp counts as changed | With no stamp, nothing shows the index is current, and the stamp is also where the collection list lives, so there is nothing to compare against. Guessing wrong here costs one extra refresh. | [P] |
| 13 | `--if-changed` also counts a collection changed when its matching file list differs from the one `refresh` recorded | `mv` keeps a file's mtime, and a deleted file drops out of the glob, so an mtime check alone never sees a rename or a delete, and the old paths stay in the index (PR #376 review). Each stamp entry lists its collection's files, and an entry without that list counts as changed, the same as a missing stamp (row 12). Cases 18 and 19 pin the rename and the delete. | [P] |
| 14 | Step 1 ends on Step 3's one-time offer of a user-level `refresh --if-changed` hook on Stop and SessionStart. The skill detects an existing hook by a command containing `memory-index.py refresh` and hands the write to the harness (`update-config` in Claude Code). | Issue #339 and its owner comments set this. Step 1 runs `refresh` once first, because a scope registered over files older than the stamp isn't stale under row 8's rule (see the `register` limitation below). The offer fires because qmd has no watcher, a scope that's never refreshed looks like poor recall rather than a stale index, and users who don't know about Step 3 never reach it. Step 3 makes the same offer because scopes registered earlier can't re-run `register`. SessionEnd was rejected: its default budget is 1.5 s (60 s max) and `qmd embed` overruns it, and Cmd-Q may skip it. Stop plus SessionStart loses at most one turn, which the next session picks up. The hook sits at user level because `refresh` covers every collection, while a project-level hook fires only in that repo. A substring match catches both command forms. The harness writes the hook so the skill keeps its "writes no hook file" rule. | [P] |

## Deliberately Not Built

| Cut | Why |
|---|---|
| Writing qmd's `index.yml` to set a collection's `ignore` list | qmd owns that file, and no CLI command writes the key. The `*.md` mask on `notes/` does the exclusion through qmd's own CLI (row 4). Pinned by a `refute_text` on `index.yml` in `scripts/memory-index.py`. |
| Running qmd as a daemon | A non-goal in #192. `refresh` is a one-shot the scope owner calls from a hook, and keeping a process alive is the user's harness's job. Pinned by a `refute_text` on `--daemon` in `SKILL.md`. |
| Refreshing on SessionEnd | SessionEnd hooks get a 1.5 s default budget, capped at 60 s, and a refresh takes seconds per qmd call. Quitting the VS Code extension with Cmd-Q may not fire SessionEnd at all. `SKILL.md` Step 3 puts the hook on SessionStart instead, which catches the last turn of the previous session. Pinned by a `refute_text` on `SessionEnd` in `SKILL.md`. The hook offer from #339 names Stop and SessionStart only, and row 14 records why. |
| A `memory_type` frontmatter filter | Folders decide collections (row 3), so passing a collection name does the filter's job. qmd's structured filter also can't read the single-line frontmatter this repo's lint enforces. Pinned by a `refute_text` on `memory_type` in `scripts/memory-index.py`. |

## Known Limitations

- A second `register` on the same scope fails. qmd refuses a duplicate collection name, so the run stops at the first `collection add` with exit 1. Remove the scope's collections with `qmd collection remove` before re-registering.
- A v1-body note keeps its transcript inline. `split-raw.sh` never splits a v1 note (no `schema` key, or `body_schema: 1`), so the mask can't keep that transcript out of `<scope>-notes`. `register` doesn't detect v1 bodies (#192's comment).
- A `[journal candidate:]` marker that sits only in the raw source text is invisible to the index, because that text is now in `notes/raw/`. Candidates flagged inside the extracted sections stay in the top-level note, so the index sees them (`inbox-to-memory/SKILL.md`, "Inside the extracted sections, flag candidates **inline**"). A lookup for the raw-only markers greps `notes/` recursively instead (#192's comment).
- `notes/CLAUDE.md` and `notes/README.md` get indexed. They sit directly in `notes/`, so the `*.md` mask matches them (row 4).
- `--if-changed` doesn't watch a collection registered after the last refresh. The stamp lists only the collections that refresh saw, so the new one is picked up the next time any refresh runs.
- `register` over files older than the stamp leaves them unembedded, and the rule doesn't count them as changed. Run `refresh` once after `register`.
- Plain `refresh` takes no lock, so it can run alongside a hook's detached refresh. Both run the same idempotent qmd commands, so the cost is wasted time, and the one that finishes last writes the stamp.
- The hook lock uses `fcntl.flock`, which exists only on POSIX systems, so `--if-changed` runs on macOS and Linux. On Windows the hook mode prints one stderr line and exits 0 without refreshing, so plain `refresh` is the only way to reindex there.
- The hook's cost grows with the largest registered collection. When nothing changed, `--if-changed` stats every file in every qmd collection, memory-index's own or not, so one large collection (`~/code` with `**/*.md`) can push it past the one-second budget. It walks each collection twice, once for mtimes and once for the file list, because `changed_since` is vendored into `find-candidates.sh` and stays as it is.
- `refresh` lists each collection's files after `embed` finishes. A file deleted or renamed while `update` or `embed` runs can stay in the index under its old path, and the recorded list already matches the folder, so `--if-changed` misses it until some other change starts a refresh.
- Step 3 checks only the hook config files it names: in Claude Code, the user, project, and local `settings.json`. A refresh hook in managed settings or a plugin goes unseen, so the skill offers a second one.

# technical-writing—rationale

Evidence tiers: **[E]** measured or observed in a real run, **[P]** practitioner reasoning from prior art, **[C]** convention inherited from this repo or its neighbors.

## Where This Came From

This ledger covers `references/review-correspondence.md` and the dispatch row that routes to it, and nothing else. The skill predates the rationale bar in `AGENTS.md`, so the router, the four layers, and the four older profiles are unledgered; a later change to one of those is the moment to add rows for that part rather than backfilling here. `PROVENANCE.md` beside this file carries the deviations from upstream, and this file does not repeat them.

- **kendrick/skills#111**, the issue. Across one wave an agent wrote nine pieces of review correspondence, eight replies answering an automated reviewer and one comment putting a set of findings on the record, and fell back to the PR-description profile every time, saying so in its report every time. The nearest row was the wrong row, and the skill said nothing about choosing it.
- **kendrick/skills#77**, the same gap filed seven weeks earlier with the opposite remedy: a `not yet written — globals above` row, no new file, the ceiling explicitly left alone. #111 supersedes it on the remedy. It stays a source because it names something #111 does not, that the description excluded "anything addressed to a person" while a reply is addressed to a reviewer, which is the collision this change had to settle before the row could be true.
- **`work-issue`, a live caller with no row to call.** `work-issue/SKILL.md:13` says `technical-writing` "writes every commit message, pull-request body, and thread reply", `:204` routes every finding reply through it, and `references/triage.md:80` repeats it. Three sentences in a sibling skill dispatched to a table row that did not exist.
- **The correspondence itself, on #115, #119 and #121**, read as artifacts rather than as history: what the good replies did that a PR description never asks for, and the one thing all of them did that a rebase has since broken.

## Decision Ledger

| # | Decision | Why | Tier |
|---|---|---|---|
| 1 | A profile file at `references/review-correspondence.md`, not the globals-only fallback row #77 proposed | The globals are sentence mechanics: one thought per sentence, "only" beside the word it changes, one name per thing. Nothing in them says the first sentence states whether the finding held, that a divergence belongs in the prose rather than in the diff, or that a cited SHA expires. Those three rules are the whole content of the gap, so the fallback row would have routed correctly to a standard that does not answer it. Tiered [P] and not [E]: #111's nine reports make the gap visible, and what the profile is worth against the fallback is what EVALS scenario 6 exists to measure and has not. | [P] |
| 2 | The row sits directly beneath `PR description` rather than at the end of the table | The reported failure is a nearest-row fallback to that one row, nine times. Putting the correct row on the next line means the same search reads the right answer on the same glance. End-of-table or alphabetical placement would be correct and would still lose to proximity. | [P] |
| 3 | The byte ceiling rises 7300 → 7800 rather than the prose being trimmed to fit | Measured. `wc -c < technical-writing/SKILL.md` was 7042 before the change and is 7436 at the end of it, so the row, its Further Reading bullet and the two repairs the row forced spend 394 bytes against 258 of headroom. That figure peaked at 7533 and came back down: a later commit trimmed the frontmatter description to bring it under its own 1024-character cap, which returned 97 bytes the ceiling decision had already been made without. 7800 therefore leaves 364, above the 112–293 band the file has run in under every previous ceiling. The slack is a side effect of that trim rather than a choice, and it is the right direction to err. 7600 was the alternative and leaves 67, below all of them, which turns the mandatory Step 2 audit into a budget negotiation. The ceiling exists to hold context load down on a model-invoked skill, so it moved by the smallest band the plan's decision rule allows rather than to whatever the prose turned out to want. | [E] |
| 4 | Neither CLAUDE.md hard rule is copied verbatim; both are restated in this artifact's scope | Both sentences carry their scope inside the sentence, "to commit messages or PR descriptions", and a review reply is neither, so a verbatim third copy ships a rule whose own text says it does not govern the file it sits in. The hard-wrap rule's stated reason is wrong here too: it cites a PR body rendering twice, where a reply renders once in a UI that turns a bare newline into a line break. The verbatim discipline exists to stop two files drifting, not to carry a scope clause into a file the clause excludes. It also keeps `PROVENANCE.md`'s "the smoke test pins both copies" and `README.md`'s "both of those profiles carry them" true, and keeps the sync at two members. | [P] |
| 5 | The SHA rule is "write the sentence so that losing the SHA costs nothing", not #111's "cite a SHA only when the branch will not be rebased" | Taken literally, #111's wording forbids what `work-issue/SKILL.md:204` mandates, a reply "with what changed and the commit SHA", and that step rebases immediately before replying, so the branch is always about to be rebased again. The SHA is correct when posted and stale when read, which makes it a locator rather than a claim. Measured: every SHA cited in the replies on #115, #119 and #121—`3fd363f`, `d38ede6`, `221eedb`, `a869637`, `7aa9413`—fails `git merge-base --is-ancestor <sha> main`, and the branches that carried them are gone from the remote. All of those replies still read, because each put the answer in prose beside the SHA. | [E] |
| 6 | The carve-out goes in the skill description, and a matching one in the README's Gotchas | The contradiction lives in the description, because that is where the excluded set is stated and the description is what decides whether the skill fires at all. In the body the new row already does the routing. `technical-writing/README.md` carried the same exclusion as a Gotcha bullet and took the same carve-out in the description's own words, since a README contradicting the skill it documents is the same defect one reader further out. | [P] |
| 7 | The Diátaxis exclusion set gains a fourth member, in `SKILL.md` and in `PROVENANCE.md` | Correspondence answers a question somebody asked; it does not occupy a document mode. Left at three artifacts while the new row's Layers cell says "no Diátaxis", each enumeration contradicts a table one section away, which this repo's review rules grade P0. A `refute_text` on `## Mode Mapping` keeps the section out of the profile for the same reason. | [C] |
| 8 | One profile with two shape sections, `## The Reply` and `## The Standalone Comment`, rather than two profiles | Register, content, hard rules and the citation hazard are identical for both, and only the opening move differs, because one has a finding above it and one does not. `commit-messages.md` and `pr-descriptions.md` each carry shape sections under a single register for the same reason. Two files would duplicate four sections to differentiate one. | [C] |
| 9 | `## Example` is a read of correspondence already posted, not a with-and-without eval pair | `comments.md` and `readme.md` both harvest from an audit pass over real files rather than a control arm, so the shape has precedent, and the suite's warning is against stubs. The material here is sixteen replies and one standalone comment, all written under the wrong profile, with the citation failure measurable by command. What it cannot produce is the profile's value over that fallback, so EVALS scenario 6 ships in the same change and is graded later, the way scenario 5 was for `pr-descriptions.md`. | [P] |
| 10 | The profile is drafted under `writing-for-agents`, not under `technical-writing` | `AGENTS.md`'s Prose section routes anything an agent consumes there, and a `references/*.md` is read by an agent at dispatch, which is the file's whole purpose. All four sibling profiles are the same kind of artifact. The circularity is only apparent: the reply fragments quoted inside the file are correspondence and are judged by the rules the file states, while the file itself is an agent document. | [C] |
| 11 | The root README drops "Four profiles ship today" rather than incrementing it to five | The count sat beside an artifact list that already included API reference, which has no profile, so five would have left a five-profile count next to a six-item list and invited the same false mapping at a new number. The sentence now says artifacts with no profile fall back to the global rules, which carries what the count carried and cannot go stale on the sixth profile. | [P] |

## Known Limitations

- **This ledger is partial.** Everything in `technical-writing` except the review-correspondence profile and its dispatch row is unledgered, so a reviewer who finds an undefended choice elsewhere in the skill has found a real gap rather than an exemption.
- **The `## Example` measures nothing.** It reads sixteen replies and one standalone comment, all written under the wrong profile, so it shows what the profile asks for and not what having it is worth. EVALS scenario 6 is the run that produces the delta and it has not been run, so decision 1 rests on the gap being visible rather than on the profile being measured to close it. The Example's "All sixteen replies lead with the verdict" is a reading taken while drafting, and this ledger did not re-derive it.
- **Nothing pins `## The Standalone Comment`.** Decision 8 keeps one file with two shape sections, and the suite asserts the file exists and pins three rules inside it, none of them in that section, so an edit collapsing it into `## The Reply` passes green. Whether the section earns its three paragraphs is the question EVALS scenario 6's standalone arm settles, and a pin written before that answer would pin whichever shape happened to ship.
- **`work-issue/SKILL.md:204` still reads "Reply to every finding thread with what changed and the commit SHA", unconditionally.** Decision 5 makes the SHA a locator that has to survive its own loss. The two are compatible, the sibling's wording does not say so, and a run reading only `work-issue` will not learn it. Outside this diff, and worth an issue.
- **This profile governs the prose and not the stance.** "Answer, never resolve" lives in `work-issue/SKILL.md:204`, and refusing performative agreement lives in `receiving-code-review`. A reply drafted under this profile alone can still be posted as a thread resolution, which destroys the only signal the reviewer has that anybody read the finding. The three compose, and none of them replaces the others.
- **The two CLAUDE.md hard rules are no longer comparable to their source by string equality.** Decision 4 buys correctness with the loss of the drift check: the two `require_text` pins on the restated sentences catch a deletion, but not a CLAUDE.md reword that should have propagated.

# technical-writing—rationale

Evidence tiers: **[E]** measured or observed in a real run, **[P]** practitioner reasoning from prior art, **[C]** convention inherited from this repo or its neighbors.

## Where This Came From

This ledger covers `references/review-correspondence.md`, the dispatch row that routes to it, and the repairs their arrival forced in the skill's other files: the byte ceiling, the carve-out in the description and its match in the README, the Diátaxis exclusion set, and the root README's profile count. It also covers the change-outline guidance in `references/pr-descriptions.md` and the two one-line descriptions that mention it, in `SKILL.md` and the README's tree, and `scripts/lint-message.py` with the sentences in both profiles that name it. It also covers `scripts/check-refs.py` and the clause in Step 2 that names it. It covers nothing else. The skill predates the rationale bar in `AGENTS.md`, so the router, the four layers, and the four older profiles are unledgered, `pr-descriptions.md` apart from its outline; a later change to one of those is the moment to add rows for that part rather than backfilling here. `PROVENANCE.md` beside this file carries the deviations from upstream, and this file does not repeat them.

- **kendrick/skills#111**, the issue. Across one wave an agent wrote nine pieces of review correspondence, eight replies answering an automated reviewer and one comment putting a set of findings on the record, and fell back to the PR-description profile every time, saying so in its report every time. The nearest row was the wrong row, and the skill said nothing about choosing it.
- **kendrick/skills#77**, the same gap filed seven weeks earlier with the opposite remedy: a `not yet written — globals above` row, no new file, the ceiling explicitly left alone. #111 supersedes it on the remedy. It stays a source because it names something #111 does not, that the description excluded "anything addressed to a person" while a reply is addressed to a reviewer, which is the collision this change had to settle before the row could be true.
- **kendrick/skills#248**, the issue. The PR-description profile told a writer what to say and nothing about showing a change's structure, so a reviewer got prose describing a call path the diff spreads across files.
- **kendrick/skills#394**, the issue. Both profiles state hard rules a script can check without judgment, and Step 2's audit is a reading pass, which is the pass `commit-messages.md`'s own Example shows missing a 74-column hard wrap.
- **kendrick/skills#401**, the issue. Step 2 asks for every path to be real at this commit, and a path a later edit renamed reads as confidently as a right one. Paths are the commonest reference in this repo's prose and the one a tool can check.
- **HumanLayer's `visual-pr`** (MIT, `4e39d8fe020f17e5810b450e2646a7c4a7aa7a74`), the source of the change-outline idea and its list of views. `PROVENANCE.md` records what was adapted and what was cut.
- **`work-issue`, a live caller with no row to call.** `work-issue/SKILL.md:13` says `technical-writing` "writes every commit message, pull-request body, and thread reply", `:204` routes every finding reply through it, and `references/triage.md:80` repeats it. Three sentences in a sibling skill dispatched to a table row that did not exist.
- **The correspondence itself, on #115, #119 and #121**, read as artifacts rather than as history: what the good replies did that a PR description never asks for, and the one thing all of them did that a rebase has since broken.

## Known Limitations

- **This ledger is partial.** Everything in `technical-writing` except the review-correspondence profile with its dispatch row, the change-outline guidance in `pr-descriptions.md`, `scripts/lint-message.py`, and `scripts/check-refs.py`, is unledgered, so a reviewer who finds an undefended choice elsewhere in the skill has found a real gap rather than an exemption.
- **The `## Example` measures nothing.** It reads sixteen replies and one standalone comment, all written under the wrong profile, so it shows what the profile asks for and not what having it is worth. EVALS scenario 6 is the run that produces the delta and it has not been run, so decision 1 rests on the gap being visible rather than on the profile being measured to close it. The Example's "All sixteen replies lead with the verdict" is a reading taken while drafting, and this ledger did not re-derive it.
- **Nothing pins `## The Standalone Comment`.** Decision 8 keeps one file with two shape sections, and the suite asserts the file exists and pins three rules inside it, none of them in that section, so an edit collapsing it into `## The Reply` passes green. Whether the section earns its three paragraphs is the question EVALS scenario 6's standalone arm settles, and a pin written before that answer would pin whichever shape happened to ship.
- **This profile governs the prose and not the stance.** "Answer, never resolve" lives in `work-issue/SKILL.md`'s Step 8 item 3, and refusing performative agreement lives in `receiving-code-review`. A reply drafted under this profile alone can still be posted as a thread resolution, which destroys the only signal the reviewer has that anybody read the finding. The three compose, and none of them replaces the others.
- **The two CLAUDE.md hard rules are no longer comparable to their source by string equality.** Decision 4 buys correctness with the loss of the drift check: the two `require_text` pins on the restated sentences catch a deletion, but not a CLAUDE.md reword that should have propagated.
- **Decision 15's trigger is unmeasured.** Scenario 5's outline arms have not run, so the structural trigger rests on reasoning. The pins catch a deleted sentence and not a writer that ignores it.
- **The trailer exemption looks only at a line's shape.** Decision 18 exempts any `Key: value` line under another, so two prose lines that both open on a one-word label, such as `Note: ...` over `Fixes: ...`, pass as trailers even when one is a wrapped sentence. git only reads trailers from the last paragraph, and the script doesn't check where the block sits.
- **The wrap check reads block starts line by line.** It recognizes CommonMark block openers on each line and doesn't model container nesting beyond a list-item fence opener, so other nested constructs, such as a fence inside a blockquote, can still misread. A list-item fence that never closes swallows the rest of the body, where a renderer would end the item at the next unindented line.
- **A span is read on one line.** `check-refs.py` matches backtick pairs within a line, so a span that wraps across two lines is missed, and a hard-wrapped body is already a `lint-message.py` failure. An abbreviation such as `i.e` in backticks has the shape of a path and is reported.

# inbox-to-memory—rationale

Evidence tiers: **[E]** measured or observed in a real run, **[P]** practitioner reasoning from prior art, **[C]** convention inherited from this repo or its neighbors.

## Where This Came From

This ledger covers `scripts/collapse-vtt.sh` (rows 1–8), `scripts/bench-fixture.sh` (rows 9–16), `scripts/migrate-scope.sh` (row 17), the link check in `scripts/lint-scope.sh` (row 18), the raw sidecar with `scripts/split-raw.sh` (rows 19–23), what phase 2.5 does with a restated `proposed` record (row 24), and phase 2.5's candidate lookup with `scripts/find-candidates.sh` (rows 25–33), and nothing else. The skill predates the rationale bar in `AGENTS.md`, so the rest of it is unledgered; a later change to another part of the skill is the moment to add rows for that part rather than backfilling here.

The collapser turns a WebVTT file into speaker turns, and its output becomes a note's `## Raw Content` zone. Phase 4 then deletes the source file, on the stated grounds that the raw zone preserved it. That chain is what makes a quiet defect here expensive: whatever the collapser emits is the only surviving record, and three P0s (#78, #84, #85) each ended in a note that read as correct while the original was gone.

The bench fixture came from #191. Nothing measured whether a scope's memory helps retrieval, so every retrieval change was a guess. Labeling is the step that usually stalls a retrieval eval, but here the labels already exist: every record names the notes it came from in `source_refs`. The script turns each `accepted` record into one `qmd bench` query whose expected files are the record and the notes it cites. A bad label here yields a recall number that looks meaningful and is wrong, and rows 10 and 11 guard against that.

The migrator moves a v1 scope onto schema 2, and `last_confirmed` is the one field it must fill in without any evidence about the record. #34 found its code comment giving the wrong reason for the default, so row 17 records the right one.

The link check in the lint came from #79. One real scope reported 17 `link-broken` failures, and every one was false. `check_links` searched `$scope` for a file named after the whole target, so a target holding a `/` could never match, and a cross-scope link could not resolve inside `$scope` at all, though `SKILL.md` calls cross-scope links fine. Its id fallback also took the last ten characters of any target, so it reported `../working-state.md` against an id, `g-state.md`, that the link never carried. Row 18 records the order that replaced it.

The raw sidecar came from #193. A groomed note used to end with its whole transcript under `## Raw Content`. The operating rule kept an agent from reading that far, but an embedding index read everything, and qmd's chunking turned a two-hour transcript into dozens of chunks competing with the three or four reviewed ones. Moving the raw text to `notes/raw/<id>.md` lets the index exclude one directory. `split-raw.sh` migrates notes groomed before the change, and `memory-index` (#192) is the consumer that excludes the directory.

The restated-record line came from #38. Phase 2.5 already body-read a `proposed` record and judged whether the input restated it, then discarded the answer, because only `accepted` records can be flagged or stamped. The phase 6 report named what the stamper stamped and declined, and a `proposed` record never reaches the stamper, so a restatement left no trace. Row 24 records the line that now carries it.

The vec lookup came from #194. Phase 2.5 found candidate records by grepping the input's entities against frontmatter, so an input that contradicted a record without naming its entity never reached it. Priya saying the bakery is moving off the vendor never greps to a record about Tolland Freight. `memory-index` (#192) registers each scope's `_memory/` types as qmd collections, and `find-candidates.sh` now runs the input's claims against them as `qmd vsearch` queries and merges those hits with the grep hits. The lookup moved out of the prose into a script because the issue's falsifiers stub qmd with a PATH shim, and an agent's hand-run grep can't be stubbed. Rows 25–32 record the choices the merge forced, and row 26 is the one the issue asked for.

## Decision Ledger

| # | Decision | Why | Tier |
|---|---|---|---|
| 1 | A cue identifier is recognized by position, one line above the timing line, and the `/^[0-9]+$/` pattern is deleted rather than widened (#78). | Position is the only thing WebVTT guarantees about an identifier: not blank, no arrow, directly above the timing line. Any pattern match covers whichever formats the author thought of, and Teams and Zoom already use `<uuid>/<n>-<n>`. Deleting it puts a numbered transcript and a UUID-keyed one on one path, so no future format needs a new rule. | [P] |
| 2 | NOTE, STYLE, and REGION open a block that runs to its terminating blank line, and a keyword opens a block only outside a cue (#85). | The three keywords share one block grammar, so one rule covers them. The `!in_cue` guard is what keeps a caption line beginning with the word NOTE as speech, since inside a cue the keyword carries no special meaning. Matches the approach `jira-refine/scripts/segment.py` took for the same defect in 3abf4c4. | [P] |
| 3 | The `WEBVTT` header is skipped as a block rather than as a single line. | The header has the same block grammar, and its `Kind: captions` line matches the `Name: ` speaker form exactly. Under the old single-line skip, a header carrying that line was one blank line away from emitting a turn spoken by someone named Kind. Not reported in any of the three issues; it falls out of the same flag. | [P] |
| 4 | Unlabelled speech is attributed to `@unknown`, never to a name inferred from a neighbouring turn (#84). | `@unknown` is the token this skill already uses for a person nobody named, in an open question's resolver field. `references/extraction-heuristics.md` gives the reason: an admitted gap beats a guess, because a fabricated name reads exactly like a fact and sends someone to ask a person who was never in the room. | [C] |
| 5 | A speakerless file emits one turn per cue, where `segment.py` merges consecutive unlabelled cues into one long `unknown` turn. | The two scripts want different things from the same input. `segment.py` needs turns to find ticket-key boundaries and carries a per-cue table to recover timing. This zone is read by a human checking a quote, and a merged turn would leave the first cue's timestamp standing for a whole meeting, so every quote after it is unlocatable. A labelled turn still absorbs the unlabelled cues after it, because the captioner said whose words those are. | [P] |
| 6 | The carriage return is stripped once, in a fall-through rule at the top of the awk program, rather than absorbed into each pattern. | WebVTT permits a CRLF terminator and Windows tooling emits one, but awk splits on the newline alone. Every rule then reads a line one invisible character longer than it looks. Widening the block opener to tolerate `\r` would fix the one rule under review and leave the next pattern to rediscover it, and the return would still ride into turn text. `jira-refine/scripts/segment.py` strips at its own read for the same reason. | [E] |
| 7 | The byte-order mark is located by the `WEBVTT` signature that follows it, not by its own three bytes. | Matching those bytes needs a `\x` escape, which is a gawk extension, or a `sprintf("%c")` comparison, whose result depends on the locale. A regex against them aborts BSD awk outright with a multibyte conversion error. Searching for the signature is plain POSIX awk and cares about neither. | [E] |
| 8 | A turn that opens with no cue behind it stops the run, rather than being emitted or silently dropped. | WebVTT permits no speech above the first timing line, so such a turn is always a preamble line the rules failed to classify, which the `@unknown` fallback then signs a name to. Two review rounds found one each, a CRLF header and a byte-order mark, and the guard catches both with their own fixes removed. Dropping the line instead would hide a real parse failure; phase 4 deletes the source once this output is written, so a loud stop is recoverable and a fabricated turn is not. | [E] |
| 9 | A query's expected files come from the record's own `source_refs`, plus the record itself, rather than from a hand-labelled set. | The user approved each record at crystallize time, citations included, so the labels are already human-reviewed. A hand-labelled set goes stale as records land, while this fixture regenerates from the scope in one command. Questions no record asks still get in through `--questions`, appended after the derived queries rather than replacing them. | [P] |
| 10 | Only an `accepted` record produces a query, and a `superseded` file never enters a record-derived query's `expected_files` (hand-written `--questions` items are taken as written, so their author owns those labels), yet superseded files stay in the scope and in the index. | A superseded record that outranks the current one is the intrusion this fixture exists to catch. Pulling it from the index hides the intrusion, and listing it as expected rewards it. A `proposed` record never got the user's sign-off, so its citations aren't labels anyone vouched for. | [P] |
| 11 | A record with any `source_refs` entry that resolves to zero notes, or to more than one, is skipped whole and named on stderr. | Recall divides by the expected files. Drop the unresolved note from the list and a retriever that never finds it goes unpenalized, so the number reads higher than it is. Guess among several matches and the label may name the wrong note. The stderr line also points at a broken link the user should fix in the scope. | [P] |
| 12 | Frontmatter is read by a small stdlib parser inside the script, not by `yq` as `lint-scope.sh` does. | The smoke suite runs this script, and `yq` isn't a test dependency. `AGENTS.md` holds scripts to stdlib Python 3. The parser covers scalars, inline and block lists, and the v1 `- note_id:` mapping, which are the shapes `source_refs` takes on disk. | [C] |
| 13 | `expected_in_top_k` is `--top-k` (default 5), raised to the length of `expected_files` when that is larger. | A record citing six notes can't put all seven expected files in a top 5, so a fixed cutoff caps its recall below 1 no matter how good retrieval gets. | [P] |
| 14 | Usage errors and a malformed `--questions` file exit 2, not the validator convention's 3. | The script produces an artifact and gates nothing, so the 0/1/3 validator convention doesn't apply. 2 matches the sibling `collapse-vtt.sh`. | [C] |
| 15 | The frontmatter reader drops an inline YAML comment, meaning a `#` outside quotes with whitespace before it, from scalars, inline lists, and block-list items, and skips full-line comments inside a block list ([PR #202 review](https://github.com/kendrick/skills/pull/202#discussion_r4226217743)). | The review ran the script on a record with `status: accepted # approved` and got exit 0 with zero queries. The comment stayed in the value, the exact `accepted` match failed, and the record vanished without a stderr line. A trailing comment also hid an inline `source_refs` list, since the value no longer ended in `]`. Requiring the whitespace keeps URL fragments intact. A quote opens a value only at its start, so the apostrophe in `Bob's` stays plain text. A mutant with the stripping disabled turns the smoke suite red. | [E] |
| 16 | A note or record under `notes/` or `_memory/` that can't be read or decoded as UTF-8 stops the run with exit 2 instead of being skipped ([PR #202 review](https://github.com/kendrick/skills/pull/202#discussion_r4226217750)). | The review put invalid UTF-8 in a cited note and got exit 0 with an empty fixture. Skipping the note left the record's ref dangling, so the record dropped out as well, and the output looked like a complete fixture. That is the partial label set row 11 refuses, and exit 2 is what row 14 already gives an unreadable scope. A mutant that restores the skip turns the smoke suite red. | [E] |
| 17 | The migrator sets a record's missing `last_confirmed` to the record's own `date`, never to the migration date or a later one (#15 added the default, #27 the stamper, #34 the corrected reason). | A migration is not a review. At migration time the migrator has no evidence that anyone re-confirmed the record, so a later date would claim a review nobody did, and the field exists so stale records stay visible. Process mode supplies that evidence later: it judges in `SKILL.md` phase 2.5 that an input confirms a record, and `stamp-confirmed.sh` then writes the confirming note's date onto an accepted record. | [P] |
| 18 | `check_links` tries three resolutions in order and stops at the first hit (#79). It tries the target as a path from the linking note's directory, then a file of that name anywhere in `$scope` where the target holds no `/`, then a file in `$scope` carrying the id. A trailing `.md` on the target is optional. The id step runs only where the target's basename ends in `-[A-Za-z0-9_-]{10}`, and a link with no id fails naming none. | 17 false failures in one real scope came from three faults: a basename search that a path can never match, a search confined to `$scope` that a cross-scope link can never satisfy, and an id taken from whatever ten characters ended the target. Trying the path first resolves cross-scope and path-bearing links alike, since the note's own directory is where its author pointed. The hyphen anchor is stricter than the alphabet test #79 proposed, because the alphabet test alone still reads `king-state` out of `working-state`; scaffolded names are `<slug>-<nanoid>`, so a real id always follows a hyphen. The id step stays inside `$scope` because its job is a file that moved within this scope. | [E] |
| 19 | A note's raw text moves to a `notes/raw/<id>.md` sidecar, and the operating rule "One groomed note per input" still holds. | That rule protects the reviewed layer: the extracted sections a person signs off on, kept in one file so nobody reconciles four. The sidecar never touches that layer. It holds only the raw text, which is never reviewed, has no frontmatter, and is reached only through the note's `raw_file`, so each input still has exactly one reviewed file. | [P] |
| 20 | `split-raw.sh` never splits a v1 body, meaning a note with no `schema` key or with `body_schema: 1`. | `references/machine-contracts.md` already promises that v1 bodies are never rewritten, and the user ruled to keep that promise on #193. Splitting would rewrite a v1 note's raw zone and its bare `(raw: L<n>)` refs. Those transcripts stay indexable until #192 excludes them another way. | [P] |
| 21 | The split shifts each `L<n>` by the line number of the `## Raw Content` heading, where `reflow-raw.sh` relocates each ref by searching for its snippet. | The split copies the bytes after the heading unchanged, so every raw line moves up by exactly that number and the arithmetic can't miss. Reflow changes line breaks, which is why it has to search. The snippet text stays as written, so this doesn't touch the issue's non-goal of rewriting quote anchors. | [P] |
| 22 | The recursive `find` in the lint's link check and in `verify-migration.sh`'s link sweep prunes every `notes/raw/` at any depth with `-path '*/notes/raw'`, and `bench-fixture.sh`'s `os.walk` of `notes/` prunes `notes/raw/`. | The lint and the sweep resolve a link by a file name ending in the note's id. A sidecar is named `<id>.md`, so without the prune a link to a deleted note would resolve to its sidecar and pass. The prune reaches every depth because a client scope's walk also descends into its project scopes' sidecars, and the pattern names no scope path because `-path` reads it as a glob, so a scope path holding `[` or `*` made `$scope/notes/raw` match nothing (#255 review). The bench indexes notes by frontmatter `id`, and a sidecar holds raw Markdown verbatim, so a pasted document with its own `id` made a record's `source_ref` resolve to two notes and dropped that record's query while the run still exited 0 (#255 review). The `notes/*.md` globs don't recurse, so they never read a sidecar as a note. | [P] |
| 23 | `reflow-raw.sh` skips a note carrying `raw_file` and counts it on its own `split notes skipped` line. It doesn't follow the pointer into the sidecar. | A split note's raw zone is one pointer line, so reflow would otherwise count it under `left alone`, which would claim the zone was read and judged not VTT when nobody read the sidecar. Fresh notes come from a `collapse-vtt.sh` that already separates turns, so reflow matters only for notes groomed before that fix, and `references/migration.md` runs it before `split-raw.sh`. | [P] |
| 24 | A restated `proposed` record is body-read, counted against the five-read budget, and named in the phase 6 report on a `restated proposed:` line, and nothing is written to it (#38). | Corroboration from an independent input is the main evidence for promoting a `proposed` record, and phase 2.5 already reads the record and forms that judgment, so dropping it threw away a finding the run had paid for. Filtering by status before the read would save the budget for records that can produce a flag or a stamp, but it makes a restatement impossible to notice, so the filter runs after. The record is still not stamped: `last_confirmed` on a claim nobody agreed to would assert a review that never happened, and `stamp-confirmed.sh` refuses a status other than `accepted` anyway. | [P] |
| 25 | Grep and vec hits merge before the header read and pass one status gate. `accepted` and `proposed` go on to the body read, and every other status drops at the header, whichever source found it (#194). | A `superseded` record's read can produce no flag, no stamp, and no restatement line, so dropping it at the header costs nothing, and the issue's second falsifier needs a `superseded` vec hit dropped unread. `proposed` stays in because row 24 body-reads it to report a restatement, and dropping it at the header would undo #38. | [P] |
| 26 | The body-read budget stays at five, vec hits draw on it, and a qmd query is not a body read. | A budget that grows with each new retrieval source stops bounding anything. `SKILL.md` already treats five-too-few as a finding about the scope's granularity, and that holds whichever lookup produced the candidates. | [P] |
| 27 | The lookup runs `qmd vsearch`, one call per claim across every type collection, with `-n` from `--top-k` (default 5). | `vsearch` is qmd's vector-only search. `qmd query` adds LLM expansion and a rerank to each call, and the header read that follows already filters the hits. The script passes `-n` explicitly because qmd's own default under `--format json` is 20. | [P] |
| 28 | The fallback is all or nothing. One failed qmd call discards every vec hit gathered so far, and the run prints exactly one `vec off:` line. | Partial vec hits make counts that describe an index that answered for half the claims. A scope missing one type collection is one `memory-index` didn't finish registering, so treating it as no index is accurate. | [P] |
| 29 | The `grep`, `vec`, and `both` counts are disjoint and taken before the status gate. | The issue makes a record a candidate when grep or vec returns it, which is before the gate. Disjoint counts sum to the candidate total, and they make `both` mean something. | [P] |
| 30 | Grep moves out of the prose into the script and matches each entity against the frontmatter block only. | `both` needs the two hit lists in one place, and the issue's falsifiers need a mechanism a PATH shim can stub. Titles live in frontmatter, so the old "frontmatter and titles" is that one block. | [P] |
| 31 | `scope_name` is vendored byte-identically from `memory-index/scripts/memory-index.py`. | It follows `AGENTS.md`'s vendoring rule. A collection name that drifts from `memory-index` fails every lookup as an unregistered scope and says nothing else. | [C] |
| 32 | `find-candidates.sh` exits 0 or 2, not the validator convention's codes. | Row 14's reasoning holds here, since the script produces an artifact and gates nothing. | [C] |
| 33 | A journal scope (`entries/`, no `_memory/`) prints `counts: grep=0 vec=0 both=0`, makes no qmd call, and exits 0. A directory with neither keeps exit 2. | Phase 1 accepts a journal scope, and phase 2.5 has never checked journal entries: the `_memory/` glob the script took over found nothing there. Exiting 2 stopped journal grooming at phase 2.5, so zero candidates is the behavior journal scopes already had (#273 review). | [P] |

## Known Limitations

- A spoken line sitting directly above a timing line, with no blank line between them, is read as a cue identifier and dropped. That input is invalid WebVTT, since cue text is terminated by a blank line, but the failure is silent when it happens.
- A speakerless transcript prints one timestamp per cue, so the raw zone reads dense where a labelled one reads as paragraphs. The alternative loses the timestamps, which is the worse trade for a zone whose job is locating a quote.
- A carriage return alone is a legal WebVTT line terminator and is not handled. awk splits records on the newline, so a CR-only file arrives as one record, matches the timing rule on the ` --> ` buried inside it, and produces no output at all. That is the #84 failure mode returning for one input class, and phase 4 still deletes the source afterward. Supporting it means setting `RS` to a regex, a GNU extension the rest of this script avoids. The preamble guard in row 8 does not catch it, because a CR-only file produces no turn at all rather than a bad one. An empty-output check would, and is not built here.
- The `Name: ` speaker form requires a capitalized first letter, so a lowercase-named speaker collapses into the previous turn as a continuation. Unchanged by this work and untested.
- `bench-fixture.sh` emits no queries for a journal scope. Journal entries use `current`, `superseded`, and `archived`, never `accepted`, and their cross-scope refs wouldn't resolve inside one collection anyway.
- A client record whose `source_refs` names a note in one of its project scopes is skipped as unresolved, because that note sits outside the client's collection. A client-scope fixture therefore leaves out every record built on project notes.
- A record with no `source_refs` emits a query whose only expected file is the record itself, and nothing goes to stderr. Retrieval scores that query on one file, so it measures little. Add a `source_refs` entry to such a record, or accept the thin query.
- The smoke suite checks the fixture the script emits, never a `qmd bench` run over it, because qmd isn't a test dependency. Whether qmd accepts the output is a manual check.
- `verify-migration.sh` still resolves a link by filename and then by its trailing ten characters, with no path step and no hyphen anchor. A path-bearing or cross-scope link that the lint passes can still fail the migration's link sweep. #79 scoped the fix to the lint.
- A link whose path resolves to a directory rather than a file fails, and so does a link to a non-markdown file. The path step tests for a regular file, and adds `.md` where the target lacks it.
- A v1-body note is never split, so its transcript stays in the note and an index over `notes/` still chunks it. #192 has to exclude those transcripts some other way, or a user migrates the note's body to v2 by hand first.
- A note split before its reflow keeps the old wall of text in its sidecar. `reflow-raw.sh` skips split notes, so nothing repairs it afterward. Run reflow first, as `references/migration.md` says, or reflow the sidecar by hand.
- A `proposed` record that overlaps an input spends one of that input's five body reads and can produce nothing but a report line. A scope heavy with `proposed` records reaches the budget sooner, and phase 6 names the input when it does.
- `vsearch` returns its top k hits whatever their similarity, so each claim brings up to k records to the header read. There is no score floor.
- An index not refreshed since records landed returns stale hits or none, and qmd still exits 0. The script can't tell that apart from no match. Run `memory-index`'s refresh after records land.
- A hit qmd returns under a path that no longer exists is skipped with a stderr line.
- The smoke suite stubs qmd, so real ranking gets checked only by a live run.
